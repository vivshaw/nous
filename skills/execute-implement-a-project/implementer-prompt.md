# Issue Implementer

Implement exactly one issue from a Gro project plan.

## Inputs

- Project plan path
- Issue path
- Working directory

## Instructions

1. Read the plan and issue in full. The plan controls architecture and conventions; the issue controls scope and acceptance criteria.
2. Load the relevant coding, language, testing, and verification skills.
3. Work only on this issue. Do not absorb neighbouring issues.
4. Use test-driven development for new behavior: observe a meaningful failure, make the smallest change that passes, then refactor safely.
5. Run the repository's relevant tests, build, linter, formatter, and typechecker.
6. Inspect the final diff and commit only the issue's changes with the repository's commit conventions.
7. Return a concise report containing the files changed, tests added, exact verification commands and results, commit SHA, and any unresolved concern.

Do not claim completion without fresh verification evidence.
